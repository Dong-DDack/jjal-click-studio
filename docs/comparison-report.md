# 동영상 → GIF 저장과 편집 복구 비교

## 실험 조건

- 고정 검사: [`tests/fixed-cases.md`](../tests/fixed-cases.md)의 T05-G01~T05-G10
- AI 공통 상한: 작업시간 45분, 사용자 요청 12회
- 브라우저: headed Chrome 156.0.8078.73
- A 시작/ B 시작 기준 커밋: [`92ffec25d9c9ce509d00cda305b66f7f9ae2ba52`](https://github.com/Dong-DDack/jjal-click-studio/commit/92ffec25d9c9ce509d00cda305b66f7f9ae2ba52)
- B 종료 커밋: [`edf5bdaeb8c1c1e2a4672d7f57e9b54f9a447fd0`](https://github.com/Dong-DDack/jjal-click-studio/commit/edf5bdaeb8c1c1e2a4672d7f57e9b54f9a447fd0)
- 공통 정상 MP4는 비공개 입력이므로 공개 저장소와 보고서에 올리지 않았다. A와 B는 동일 SHA-256의 파일을 로컬에서 별도로 사용했다. 오류 입력 `invalid-media.mp4`는 고정 검사표에 따라 사용했다.

## 이름을 가린 결과

| 측정 항목 | AI A | AI B |
|---|---:|---:|
| 실제 작업시간 | 시작 시각 미기록, 산출 불가 | 시작 시각 미기록, 산출 불가. 기록된 첫 브라우저 작업~마지막 검사 구간은 약 50분(12:48~13:38)이라 45분 상한 준수 확인 불가 |
| 사용자 요청 수 | 1회 | 1회 |
| 고정 검사 통과 수 | 0/10 확정. 고정 MP4 사용을 확인하지 못해 부분 관찰은 통과로 세지 않음 | 10/10 |
| 실패 회차 수 | 산출 불가. 완전한 고정 검사 회차를 확인하지 못함 | 산출 불가. 실패가 발생한 초기 시도의 회차별 집계가 남지 않음 |
| 코드 변경 | 없음 | `media.js` 최소 수정 |
| 소스 버전 | 시작 `92ff…`; 종료 HEAD도 `92ff…` (코드는 변경되지 않음) | 시작 `92ff…`; 종료 `edf5…` |

모델·서비스 이름은 이 비교표에서 가렸다. AI A는 기존 편집기 화면으로 일부 동작을 관찰했지만 고정 입력 검증을 완료하지 못했다. AI B는 고정 입력으로 검사를 다시 시작했고, 첫 프레임 seek 시간 초과를 재현한 뒤 구간 적용 중 재생 seek를 제거하고 GIF 변환 전 영상을 일시정지해 진행 중 seek가 정착되도록 수정했다. 수정 뒤 같은 Chrome 세션에서 G01~G10을 통과했고, G04/G07/G10은 실제 `.gif` 다운로드(GIF89a, 480×480)로 확인했다. 보조 자동 검사 `gif-export`, `history`, `template-media`도 모두 통과했다.

### 상한과 기록의 한계

AI A와 B의 정확한 시작 시각이 기록되지 않아 45분 시간 상한 준수 여부를 확인할 수 없다. B 기록의 12:48~13:38은 브라우저 작업 관찰 구간으로, 전체 작업시간의 정확한 측정값이 아니다. 따라서 시간과 실패 회차를 추정값으로 채우지 않고 산출 불가로 표시했다. A 종료 시 HEAD는 시작과 같았으나 A의 HANDOFF 수정은 미커밋 상태로 B에게 전달됐다. B 시작도 같은 HEAD였고, 최종 코드와 실행 기록은 B 종료 커밋에 고정됐다.

## 재현 확인 방법 4줄

1. **위치:** [딸깍 짤·카드 스튜디오](https://dong-ddack.github.io/jjal-click-studio/)를 엽니다.
2. **행동:** 호환되는 MP4를 불러오고 1초 시작·3초 길이를 적용한 뒤 GIF를 저장합니다. 이어 취소 후 문구를 추가·이동하고, 저장소의 `tests/fixtures/invalid-media.mp4`로 오류를 확인한 뒤 정상 영상을 다시 저장합니다.
3. **통과:** GIF 파일이 실제로 내려받아지고, 취소·오류 뒤에도 영상과 편집기가 유지되며 문구를 추가·이동할 수 있습니다.
4. **실패:** GIF가 다운로드되지 않거나 변환이 멈추고, 취소·오류 뒤 편집기가 응답하지 않거나 기존 작업이 사라집니다.

고정 정상 MP4는 개인정보 보호를 위해 공개하지 않았다. 재현 확인에는 방문자가 준비한 호환 MP4를 사용한다. 이는 동일한 입력 파일을 이용한 비교 결과 자체를 재현하는 절차가 아니라 앱 기능의 공개 확인 절차다.

## AI와 나의 판단 3줄

- **AI에게 맡긴 일:** 고정 검사 실행, 재현된 GIF seek 문제의 최소 수정, 자동 검사와 HANDOFF 기록을 맡겼다.
- **내가 직접 판단한 일:** 동영상 구간 GIF 저장을 개선 대상으로 고르고, 공통 검사·상한·입력 보호 조건을 정했다. A/B 시간 측정이 빠졌다는 사실은 산출 불가로 남겼다.
- **AI 제안을 따르지 않은 일:** 시간 기록 누락을 보완하려고 새 실험을 반복하자는 제안 대신, 현재 결과를 제출하고 측정 한계를 공개하기로 했다.

## 다음 작업의 도구 선택 기준

고정된 사용자 흐름을 빠르게 확인할 때는 실제 브라우저를 우선하고, 브라우저에서 재현된 결함을 좁혀 수정해야 할 때는 코드 분석과 자동 검사를 함께 제공하는 코딩 에이전트를 사용한다.
